## g3h fix of the last function (17.10.2026) - `mi_mempool_refill_work`
Cause (found with `-mllvm -print-after-all` + the lesson of miloadtrace/mist STATUS.md): compare polarity comes from IR block order. clang puts the single shared UBSAN local-bounds trap block right after the FIRST bounds check of the function in source order. Here that first check was the in-loop `refill_logs + pos` check, so the trap block was the IR-next block, the DAG kept `ult 301 -> body` (`cmp #0x12d; b.lo`). In the stock the first check lies earlier, the loop body is the IR-next block, the DAG inverts `uge 301` to `ugt 300 -> trap` (`cmp #0x12c; b.hi`, later flipped to `b.ls body; b trap` by block placement).
Fix (HACK, codegen only, no semantic effect): at the top of the `for (;;)` loop `char __maybe_unused dummy = refill_logs[pos];` (an earlier, optimised-away array-bounds check moves the trap block). 1 iteration, 0 word diff.
