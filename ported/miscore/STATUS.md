Reference: OS4 stock `vendor_dlkm/miscore.ko` ("module for xiaomi net score", Wei Liu). No public template: reconstructed from the disassembly. Files: `miscore_core.c` (everything except netlink), `miscore_nl.c` (family `nl_miscore`, send/handle, init/exit), `miscore.h`. TWO translation units like the stock (the ThinLTO import limit decides what is inlined: `miscore_nl_exit/init` stay out of line, only `miscore_debug` is a shared global). The core file is not named miscore.c because Kleaf refuses an output name equal to a source name when there are several sources. Fast loop `g1f_tools/qq.sh miscore` (FD="fn ..." prints diffs), Bazel `g1f_tools/bz.sh miscore`.
What it does: 4 netfilter hooks (IPv4/IPv6 LOCAL_IN prio 1, POST_ROUTING prio -1) count TCP/UDP traffic of the foreground apps (up to 4 uids) per interface (up to 4 links, `miscore_link_info_st`, 112 bytes = `network_para_st` 96 bytes + if_name[16]); retransmissions (seq < snd_nxt), out-of-order downlink classes by `icsk_ack.lrcvtime - jiffies` (-50/-25/-5), srtt running average; a timer (period default 1000 ms, sysctl `net/miscore/{miscore_enable,miscore_debug}`) sends the table over generic netlink (family `nl_miscore`, cmd 1 = config with attrs 1 enable / 2 foreground apps / 3 link change / 4 period; report cmd 2 attr 5) and clears the counters. Struct/enum/field names come from the stock BTF (`START_ID=141631`, `tools/btf_dump_startid.py`, dump in `_ref/btf.txt`); the KCFI hashes depend on them (`struct miscore_link_info_st *p_link_info`, `miscore_nl_send_msg(void*, int, u8, u8)`).
Facts verified by the compare: READ_ONCE under LTO = `ldar`; `ip_hdr()` is evaluated BEFORE `skb_to_full_sk()` in the hooks (decides where the loads sit); the foreground lookup is an unrolled loop with `spin_unlock_bh` inside the match and after the loop (no flag variable); TCP branch written first in the update_* functions; `update_uplink_link_stat_v4` has no `!iph` test, the v6 variants have none either; the retrans printk exists only in the v4 uplink path (`update_uplink_tcp_state(..., bool log)`, always_inline); `len` of `miscore_send_link_info` is computed before the unlock; the three OOO counters are bumped before packets/bytes; `refresh_link_info` zeroes the 22 counters field by field (not rtt, not if_index).
Documented hacks: none (no forged CRCs, no pads).
Still different (5), all code layout / register allocation, no behaviour difference:
- `miscore_input_hook4/6` (stock 183/177 insns, ours 179/173): the stock compares `proto == TCP` first and keeps the small TCP stub (`w21=0; if (sk) goto common; else return`) out of line, UDP inline; ours tests UDP first (UDP-first source) or puts TCP inline (TCP-first source / switch). Tried if/else in both orders, switch, likely/unlikely, merged conditions (variants in `g1f_tools/v/w*.txt`).
- `update_uplink_link_stat_v4/v6` (4 words): register assignment of the srtt average `madd` (stock `madd w10,w9,w10,w8`, ours `madd w8,w10,w9,w8`); 8 expression/local-variable forms tried.
- `miscore_handle_link_change` (stock 286 vs ours 274 insns): the stock unrolled "find empty slot / already exists" loop is jump-threaded into branches (no `csel`, `cbz w8` on the first entry acts as the "empty found" flag, constants 0..3 in w20); ours keeps a csel chain. Tried zero-test first / equality first, `continue`, `< 0` forms.
Not hardware-tested.
