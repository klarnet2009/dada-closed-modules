## Third-party firmware (HARD RULE, kept)
The stock module embeds ~25 MB of third-party UFS microcode (Hynix, Kioxia, Samsung, Micron, YMTC). NONE of it is in this tree or in this file.
- `ufs_ffu_blobs.h` declares the 30 blob symbols as `extern const unsigned char NAME[]` (names only).
- `ufs_ffu_blobs.S` defines them ZERO FILLED with the stock names, sizes and .rodata offsets (generated from the stock symtab by `work/a17/g4f/gen_ufs_ffu_tables.py`, which reads names/sizes/offsets only, never section bytes). A module built from this tree contains NO valid firmware: it must never be flashed to a device with a matching UFS part and is not meant to replace the stock .ko. A real build must replace the `.zero` fills by `.incbin` of vendor images kept outside the repository.
- `ufs_ffu_table.h` = `need_update_k[81]` (vendor/product/rev strings, blob symbol, size): table data only (names of UFS parts, sizes), no firmware bytes.
- Only the 3 `*_len` int variables (value 786432) are defined in C.

## Source-form findings (what made the code match; reusable)
- Locals must be declared at FUNCTION scope (C89 style) in `ufs_read`/`ufs_write`: block-scope locals get `llvm.lifetime.end` at the loop latch, which makes LoopRotate rotate the loop; the stock loop is unrotated (latch with the exit test).
- `cmd[16]` must carry no auto-init at function entry: `__attribute__((uninitialized))` (hack, listed below) reproduces it; per iteration `memset(cmd,0,16); cmd[0..5]; cmd[6]=0; cmd[7]=n>>8; cmd[8]=n` (explicit cmd[1]/6/7 let DSE trim the memset like the stock).
- `unsigned int end = lba + nblocks; if (part_info.start + part_info.size < end) return -EINVAL;` (the add before the loads).
- `hba->host->eh_noresume = 1` is the first statement after the get-device check (before the CDB bytes) in `ufs_scsi_write_buf` (scheduling).
- CRC-32 helper must be `__always_inline` (stock has it inlined twice: compare, then recomputed for the "diff" print).
- The stock kzalloc'd the 4 KB check buffer but used kmalloc+memset for the 4 KB header, the table and the firmware buffers.
- Kleaf DDK accepts `.S` sources but not `.inc`; the table is `ufs_ffu_table.h`.

## Open / hacks (honest list)
- `__attribute__((uninitialized))` on `cmd` in `ufs_read`/`ufs_write` (codegen hint, not necessarily in the original); `noinline` on `ufs_fw_update_write`; `__always_inline` on `ffu_crc32`; `#pragma clang diagnostic ignored "-Wreturn-type"`.
- `ffu_ffu_delayed_work`: the four early exits of the LUN loop ("one time entry", "bootreason was set", "proc name is null / not ufs") are written as `msg = KERN_xxx "..."; goto out_msg;` with one `_printk(msg)` at the end (a plain `pr_*(); return;` per exit is NOT merged by LLVM here; the stock clearly has one printk with a PHI of the strings, so this is probably how the original was written), the locals `bootreason`/`batterystatus` are assigned by statements right before `of_find_node_by_path` (not initialised at the declaration), all locals at function scope. Result: exact match.
- `start_ffu`: stack frame is 0x10 bytes smaller (0x130 vs 0x140) even with all locals at function scope and zeroing as statements (tried 3 C89 variants); the stock hoists `&info.product`, `&info.rev_to`, `&dev.rev` and the record base into spill slots/callee-saved registers (LICM of frame addresses + spills), which shifts every `[sp+x]` and the register allocation (75 hunks, but only the layout differs; strings/loops/fortify/bounds are present, 649 vs 645 insns). Next steps: find the extra spilled value(s) (e.g. `ffu_count` kept in a slot, `size` ALIGN form, the 2nd CRC call in the printk arguments, `table`/`n` as separate objects), try `info` accessed through a pointer.
- Stock `.rodata` has a 3.8 KB gap between `MICRON_4_0_256_0212` and `MICRON_4_0_512_1T_0212` (not a symbol); reproduced as zero padding in the placeholder.

## goal-G4g round (start_ffu 75 -> 15 hunks, real Kleaf build confirmed: function set/relocs/objects/imports/modinfo OK, bytes differ in 3 functions)
Four source-form findings, all applied to ufs_ffu_main.c:
1. CRC-32 bit step must be the mask idiom `crc = (crc >> 1) ^ (0xEDB88320 & -(crc & 1));` (the ternary gives csel code); with it LLVM produces the stock branchless xor-tree and the hoisted constants (0x76dc419 etc. in registers), which removed most of the extra register pressure / spill slots (75 -> 48 hunks).
2. Stack layout: frame slots are assigned in alloca order, first alloca nearest the canary. The stock has hdr and info nearest the canary, dev lowest, AND zeroes hdr/info only after the first printk. Both facts are explained by ONE thing: hdr and info are locals of an inlined helper (inlined allocas go first in the caller's entry block, their auto-init zeroing sits at the inline position). Now `ffu_load_table()` (static __always_inline: page read, header check, merge of the partition records into the table) holds `hdr`, `info`, `table`, `n`, `page`; start_ffu keeps `dev` (75 -> 22 hunks; frame 0x140 reached).
3. `memcpy(&table[n], &info, sizeof(info)); n++;` (not `&table[n++]` inside the call): only then the fortify object-size check `size - n*48 >= 48` of the stock appears (22 -> 18).
4. `blk = addr >> 12;` as a separate statement BEFORE `size = (info.size + 0xfff) & 0xfffff000;` (stock spills addr>>12 and size together as an stp) (18 -> 15).
Left in start_ffu (15 hunks, 643 vs 649 insns): (a) stock keeps `fwbuf` and the 64-bit `size` in spill slots ([sp+0x28], [sp]) and the sdev in [sp+8], n as a 64-bit slot; (b) the CRC loop bounds-trap hoist: stock emits `umin(size,2^63) == umin(size,len-1)` (7 insns: ldr, mov, sub, cmp/csel x2, cmp, b.eq) in the preheader, we emit the simplified `cmp len-1, size; b.hs` (2 insns) twice (both CRC loops). ffu_crc32 spellings tried (len u32/int/size_t/ulong x i u32/int/u64 x for/while/ptr): int/int changes the loop guard to `cmp w8,#1; b.lt` (worse); everything else gives the same 15 hunks.
ufs_read / check_ffu_parition_fw_error: the order of the two `stp xzr,xzr` of `struct scsi_exec_args` (stock: [sp+0x20] first, then `ldr hba->host`, then [sp+8]) was attacked again with 10 more variants (hoisting `host = hba->host` before/between the sshdr/args init, `gen_args4.py`): all worse (8-14 hunks). 3 iterations spent, not solved.
Tools: work/a17/g4g/ (copies of the g4f scripts with <work-dir> paths; gen_crc.py, gen_crc2.py, gen_decl.py, gen_tn.py, gen_blk.py, gen_args4.py, xf_helper.py = the helper refactoring).
Hacks (unchanged list + this round): `ffu_load_table` as an always_inline helper is a layout hack (probably how the original was structured; not proven).

## goal-G4i round (17.10.2026): no source change, findings only (start_ffu still 15 hunks, ufs_read / check_ffu_parition_fw_error 2 hunks each)
- start_ffu CRC-loop trap, root cause located (IR dumps with `ld.lld -mllvm -print-after-all -mllvm -filter-print-funcs=start_ffu`): the hoisted check is created by IndVarSimplify from the exit counts of the 2-exit CRC loop (`i < len` and the local-bounds check against the kmalloc size). Ours (IV widened to i64: `umin(zext(len)-1, size)`, folded by InstCombine to `cmp len-1, size; b.hs`); the stock keeps `(u32)(len-1)` computed in 32 bit (`sub w9,w8,#1` then used as x9) and `umin(size, 2^63)`, i.e. the stock loop IV was NOT widened to 64 bit by indvars and `size` kept a clamped SCEV. So the target is a loop shape whose 32-bit IV is not widened.
- Tried this round (all keep the 15 hunks or are worse): 15 forms of the buffer size (`int`/`long`/`unsigned long`/`u64`/`size_t`/`unsigned int` x `(info.size + 0xfff) & 0xfffff000`, `ALIGN`, `round_up`, `/4096*4096`, `>> 12 << 12`, `& ~4095`, 64-bit arithmetic; the u64/u32 forms are 58-59 hunks because `size` is then zero-extended, not `sxtw`; the stock keeps `sxtw x28,w8` so the `int` form is right) (`work/a17/g4i/gen_sz.py`); 8 IV-keeping forms of `ffu_crc32` (`asm volatile` use of `i` after / inside the loop, `i != len`, `data + (u32)i`, do/while with `len` guard, `crc + (i - len)`, `barrier()`, `while`) (`gen_iv.py`): `i != len`, `data + (u32)i`, do/while, while and `crc + (i - len)` leave the code unchanged (IV still widened), the asm/barrier forms are worse (19-28 hunks).
- Stock detail worth knowing: `size` exists twice in the stock: `str x28,[sp]` (64-bit sext copy, reloaded for the check) and `stp x9, x8,[sp,#0x18]` (blk and the 32-bit size, passed to ufs_read).
- ufs_read / check_ffu_parition_fw_error: not retried (scheduling of two `stp xzr,xzr`; a probability hint does not change scheduling).
Tools: work/a17/g4i/ (gen_sz.py, gen_iv.py, vrun2.sh, vall.sh, dx.sh).
