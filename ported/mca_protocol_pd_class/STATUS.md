# mca_protocol_pd_class - PARTIAL (66 of 74 functions byte+relocation identical; 49 of 52 export CRCs ok; reference = OS4 stock)

SAFETY: charging module (`mca_*`): source for the community only, never flash it / never put it into a ROM build.

Template: XRING `mca/mca_protocol/protocol_pd/mca_protocol_pd_class.c`. The OS4 stock is the HyperOS 3 one plus a few changes (OS3 -> OS4 differ in 6 functions + 2 new callbacks), the template is NOT the same revision.
Public header `stubs_a17B/include/mca/protocol/protocol_pd_class.h` is GENERATED by `work/a17/portB/gen_pd_header.py` (ops struct with its 50 callbacks from the HyperOS 3 BTF dump `work/a17/portB/btf_pd3.txt`, BTF type codes T8/T11/T32/T747/T1329... mapped to
`unsigned int/int/int */unsigned int */bool */...`; prototypes from the template definitions for the 52 stock exports); (OS4's own BTF cannot be decoded by btf_dump.py local: no base-type start id).
Changes vs template: removed the 4 exports the stock does not have (`get_usb_communication_support`, `reset_pps_stage`, `set_has_dp`, `set_otg_plugin`), added `protocol_class_pd_set_typec_cc_orientation`, removed the XRING debug `return 0;` in
`protocol_pd_update_port_num` (stock reads the real `g_cur_port`: that alone fixed ~25 wrapper functions), added the missing includes/constants (typec attach modes 0..3 proven by `mode-1 < 3`, SYSFS_DEV_3 "typec", PROTOCOL_PD_MAX_PDO_NUMS 7).
Result: compiles; 66/74 functions identical in the ThinLTO-emulated link; exports 49/52 CRCs equal.
Remaining (OS4 new code, must be transcribed from the stock disassembly):

- new notifier callbacks `protocol_pd_connect_cb` (if `action == 0` it clears a static int, probably `device_max_power`) and `protocol_type_change_cb` (if `action == 6` it fills a local int through a call and stores

- `protocol_pd_class_probe`: new DT keys (`disable-low-power-fix`, `keep-report-max-power`, `support_mode`, ... via `of_property_read_bool`: the OS4 stock imports `of_find_property` and `charger_partition_get_eu_model`);
