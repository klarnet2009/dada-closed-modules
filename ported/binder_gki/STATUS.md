So the stock probe type already contains `bool *should_fail`.

  (= `i >= TOKEN_BUFF_SIZE` on the exit value). In every shape we compile, the compiler knows `len <= 140` (umin clamp) and folds that post-loop check away (or, with a pointer compare, keeps it in a different shape); ~45 spellings tried in the 0.5 s ThinLTO loop (`work/a17/g4d/gen_bt.py`: goto/break/while(cnt--)/index/pointer/int types/n=len-18 hoisted/etc.). - Hook prototype drift (documented for the main session): our 6.6.144 GKI declares `android_vh_binder_alloc_new_buf_locked(size, free_async_space, is_async, bool *should_fail)`, i.e. an EXTRA `bool *should_fail` argument that the stock 6.6.57 probe lacks (stock probe `mi_binder_alloc_new_buf_locked(void *data, size_t size, size_t *free_async_space, int is_async)`).

## What was recovered (verified against the asm)
- `oem_binder_hook_set` = `struct oem_binder_hook` (same as `binder_oem.h`); statics `get_binder_lock` (mutex *), `get_binder_hhead` (hlist_head *), `bgot` set by the `android_vh_binder_preset` probe `mi_get_hhead_and_lock(data, hhead, lock, proc)`.
- `reset_isfrozen(uid, pid, found, proc)`: refuses in_interrupt / hardirq / softirq / preempt_count > 0 (four printk), then under `*get_binder_lock` + `proc->inner_lock`: returns 0 (no tsk / not frozen-state found), 2 (`!proc->is_frozen`), or clears `proc->is_frozen` (stores BEFORE the printk) and returns 1.
- `query_binder_app_stat(uid)`: walks `*get_binder_hhead` (hlist of `binder_proc`), for procs whose `real_cred->uid == uid` computes a state with `millet_binder_switch` on: BINDER_PROC_IN_BUSY (3, a sync transaction with `need_reply` and no `to_thread` in `proc->todo`), BINDER_THREAD_IN_BUSY (2, such a transaction in a thread's todo for that thread),
  BINDER_IN_TRANSACTION (4, `thread->transaction_stack` with `to_thread == thread` and `need_reply`); with the switch off: 3 if `proc->todo` non-empty, 2 if a thread todo non-empty, 4 if a thread's `transaction_stack->to_thread == thread`. Calls `oem_query_st_hook(uid, current, 0, current->pid, !all_idle)` under the mutex.
  Matching trick (reusable): after `spin_lock(&t->lock)` the stock RE-READS `thread->transaction_stack` (it uses `thread->transaction_stack->to_thread` and `->lock` directly, but the local `t` for `need_reply`); the dummy rcu read is `rcu_read_lock(); (void)__task_cred(tsk); rcu_read_unlock();` (not `task_uid()`, which takes the lock itself);
  `idle = (stat == 0) && idle;` fixes the operand order of the final `and`.
- `mi_binder_wait_for_work`: matching needed `bool dead = thread->is_dead; t = thread->transaction_stack;` loaded in that order AFTER the hook test (otherwise SimplifyCFG hoists the `t` load above the hook test and merges the two unlock paths).
- `mi_binder_transaction`: `preempt_enable()` around the trans hook when `preempt_count() == 1` (re-`preempt_disable()` afterwards); with `millet_debug`: for ONEWAY transactions to targets with uid >= 10001 that are `freezing()` / `cgroup_task_freeze()` / `cgroup_task_frozen()` it copies up to 140 bytes of the transaction data
  (`copy_from_user`), extracts the ASCII interface token from the UTF-16 data at offset 16 (every second byte) into `desc[140]` and prints `millet_kernel calleruid:%d callerPid:%d targetUid:%d targetPid:%d  code:%d  desc:%s` (KERN_ERR, no module prefix).
  Everything up to and including the `__arch_copy_from_user` call is byte-identical; what differs is the token-extraction loop: stock is a pointer loop with trip count `((len-18)>>1)+1` guarded by `len >= 18`, followed by `if (len-18 >= 0x116) desc[139] = 0`,

- `oem_register_binder_hook`: struct copy `oem_binder_hook_set = *hook`; the stock's load/store pairing is (0x18,0x20) (0,8) (0x28,0x30) (0x10): the order differs from every spelling tried (struct assignment, memcpy, field-wise) = 10 words.

`mi_binder_transaction` is now byte-identical (real build `<work-dir> binder_gki` -> EQUIVALENT). Two source-form findings, both in the token loop:
- the trip count `cnt = (len - 18) / 2 + 1` is computed BEFORE the guard (not inside it): inside the guard the sub gets nuw from the guard, InstCombine proves `i >= 140` dead; outside, the post-loop check keeps the stock closed form `cmp x8,#0x116; b.lo; strb wzr,[sp,#0x93]`;
