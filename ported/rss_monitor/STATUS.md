# rss_monitor - PARTIAL (31 of 32 functions byte-identical; function set, relocations, objects, 0 exports, 51 imports+CRC, modinfo all OK in the Bazel compare)
Reference: OS4 stock `vendor_ramdisk|vendor_dlkm/rss_monitor.ko` (author gaoxiang17, "Per-process RSS memory change tracking via tracepoints"). No public template: reconstructed from the disassembly. Kleaf DDK ThinLTO build `g1d_tools/bz.sh rss_monitor`, fast loop `g1d_tools/qq.sh rss_monitor` (FD="func ..." prints diffs), variant runner `g1d_tools/var.py`.
What it does: tracepoint `rss_stat` (enabled through /proc/rss_monitor/enable) and `sched_process_exit` (always); per thread-group-leader entry (`rss_track_entry`, 64 bytes, hash table of 1024 hlist heads `hash_32(tgid,10)`, `kmem_cache rss_track_entry`) remembers the last RSS of the 4 mm counters; when |new-old| >= rss_threshold (pages, default 3072 KB = 768 pages), the per-entry time throttle (2500 ms) and the global rate limit (event_threshold = 10/s, `rss_rate_allow`) and `max_pending_works` (256) allow it, a work item (`rss_nl_work`, 112 bytes, workqueue `rss_mon_wq`) sends a generic-netlink multicast (family `RSS_MONITOR`, group `events`, attrs 1..7: type 50004, tgid, ppid, uid, comm[16], new RSS bytes[4], old RSS bytes[4]). /proc/rss_monitor/{enable,rss_threshold,time_threshold,debug,event_threshold,max_pending_works,stats}; `debug` toggles a static key (`rss_mon.debug_key`, embedded in the 8360-byte `rss_mon` struct) guarding all log lines and the probe timing (probe_avg_ns).
Port facts verified by the compare: probe uses `current` and falls back to `mm->owner` (`unlikely(current->mm != mm)`), only thread-group leaders, not PF_KTHREAD; `rss_ht_try_insert/rss_check_and_report/rss_comm_filtered/rss_rate_allow` are `noinline` (stock keeps them as functions); `(val << 10) >> PAGE_SHIFT` (ubfx) for KB->pages; `unlikely()` on the threshold test in rss_stat_probe (decides register allocation); all log prints in rss_nl_send_work are under the static key; `struct work_struct` of this GKI has 2 KABI reserve words (work item = 0x30 + payload); `event_threshold`/`max_pending_works` writes reject 0.
Documented hack: none (no forged CRCs, no pads).
