# dump_binder - PARTIAL (10 of 11 functions byte-identical, the 11th has the stock size and layout and differs only in register naming; function set, relocations, objects, 0 exports, 38 imports+CRC, modinfo all OK in the Bazel compare)
Reference: OS4 stock `vendor_ramdisk|vendor_dlkm/dump_binder.ko` ("Xiaomi binder async buffer monitor"). No public template: reconstructed from the disassembly. Kleaf DDK ThinLTO build `g1d_tools/bz.sh dump_binder`, fast loop `g1d_tools/qq.sh dump_binder` (FD="func ..." prints the diff of those functions).
What it does: hooks `android_vh_binder_proc_transaction_finish`; for async (oneway) transactions into `system_server` it checks `alloc.free_async_space <= alloc.buffer_size/10` (low) and, when the oneway-spam flag is set, whether one sender's async buffers use >= buffer_size/4; the status bits (1 = spam, 2 = low, 4 = event) go into `low_buffer_status_mask` (atomic_t), a snapshot (`binder_info`: pid, comm, timestamp, sizes, up to 512 `binder_buf_node` of the offending sender with target node ptr/cookie, code, start_time) is taken under `binder_info_lock` and `binder_mem_event_poll` is woken. `/proc/mi_bindermeminfo` (0600, uid/gid 1000): read = `bindermeminfo_show`, write "1"/"0" = start_monitor/stop_monitor (registers/unregisters the vendor hook). The private binder structs come from the GKI tree (`binder_internal.h`, `binder_alloc.h`, `dbitmap.h` copied into the package; layout verified: binder_alloc at proc+0x1a8, binder_buffer 6.6 layout, transaction->buffer +0x60, start_time +0x88).
Port facts verified by the compare: `atomic_and(~4)` (immediate, not andnot), `atomic_fetch_and(~3)`, plain `is_monitoring` store with `READ_ONCE` loads, local `poll_wait` without the 6.6.144 barrier (only `wait && wait->_qproc`), `list_for_each_safe` + `if (node)` in clear_binder_info_locked, `count >= 127` -> -EINVAL in write, `comm` copied with fortified strlen + memcpy + NUL, `binder_alloc_buffer_size()` copied from binder_alloc.c.
Documented hack: `list_add_tail_inl` (`__always_inline` copy of list_add_tail) - the stock inlined list_add_tail into the hook, our CFG makes the callsite 'cold' (inline cost 65 > threshold 45) so the real one stays out of line.
