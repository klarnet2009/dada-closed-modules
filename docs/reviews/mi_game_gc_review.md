# Review of the G14c mi_game port (GC booster + changed logic) against the GLOBAL OS4.0.0.7 stock, 19.10.2026

Independent, read-only behaviour review. Stock = `<work-dir>` (md5 fe4ba456..., same as `<work-dir>`), CN stock = `<work-dir>`, ours = G14c Kleaf build `<work-dir>` (built from the current `work/re/src/mi_game` sources). All disassembled by me with `llvm-objdump -dr` (clang-r510928). Layouts: `pahole -F btf` on `<build-dir>`, public WALT governor `<build-dir>`, stock `sched-walt.ko` and `plat_common.ko` of the global set. Nothing was loaded, flashed or run on the phone; no git; sources not modified. Scratch `<work-dir>` (6.6 MB: dumps + `fx.py` function extractor/normaliser, `hooks.py` hook-sequence extractor).

## Verdict

The GC port is faithful except ONE real behavioural defect introduced by G14c (migt_hardwork, gc_cnt for the main GC thread in the ranking loop). Everything else of the G14c change set is byte-identical to the stock (modulo relocation names) or semantically identical with verified offsets. Two old CN-level error-path / width differences remain (not introduced by G14c, low). Status PARTIAL / DO NOT LOAD stays; nothing here is a crash risk in normal operation.

## Per item

1. **migt_game_schedule (hook 40): MATCHES** (byte-identical except rodata reloc names; kCFI preamble 0x40d4faad = what `plat_mi_game_schedule` checks). Offsets verified by pahole on our vmlinux BTF: `__state` @0x30 (48), `on_rq` @0x80 (128) (also `usage` 0x40, `real_cred` 0x818, `comm` 0x830, `android_vendor_data1` 0xbc0). Order: gc_booster_enable, fortified strnlen(gc_thread_name,16), strnlen(gc_main_thread_name,16), game_main_gc_task(prev), prev != next, `!prev->on_rq` (plain ldr), `READ_ONCE(prev->__state)` (ldar), `is_doing_gc = 0` (plain str). STOCK-LEVEL FINDING (same in ours): slot 40 has NO caller in the whole global module set (vendor_ramdisk + vendor_dlkm + system_dlkm: no importer of `plat_mi_game_schedule`; `g_plat_hook_table` is not exported; plat_common never calls the wrapper internally). So on this firmware migt_game_schedule never runs and `is_doing_gc`, once set by the wake-up hook, latches until `/dev/migt_reset` release or `gc_booster_enable=0` (gc_booster_reset). While latched: exclusive cpus off and xr_set_next_freq forces `policy->max` on every cluster. Faithful to stock, but a power/thermal risk if user space enables the booster.
2. **migt_hardwork: DIFFERS (D1)**, rest MATCHES: all three stale-mark clears use `~0x31d6` (`mov w9,#-0x31d7`, stock and ours at the same three sites; CN had `~0x1d6`); gc_cnt = 0 before the delay walk (stock `str wzr,[sp,#0x1c]` on both the empty and non-empty path); delay walk: task != NULL, GC_NAMES_SET in stock order, `strcmp(comm, gc_main_thread_name)==0 -> |=0x2000, cnt++`, else `strncmp(comm, gc_thread_name, strnlen)==0 -> |=0x1000, cnt++`, then put_task_struct; ranking loop: stask (sel == i) path has no GC test; non-stask: GC test (task NULL check after the strnlens, as stock), GC-tagged entries get no vip/ip bit, windows `i < (int)(stask+gc_cnt+vip)` -> 0x10, `< +ip` -> 0x4 (stock: 32-bit add, `cmp x22, w8, sxtw`). Call multiset of the whole function identical except local-name/list_add-inline residuals known since G1ak; same 9 acquire loads. game_gc_task (0x3000) has no caller in stock or ours; game_main_gc_task (0x2000) is used by the wake-up hook and migt_game_schedule in both.
3. **!is_doing_gc gate: MATCHES** in migt_reserve_usable / reserve_usable_inl: stock order `migt_enable && enable && vote && (u32)reserve && !(reserve & ~online[0]) && !atomic_read(is_doing_gc)` (ldar). Callers: migt_choose_exclusive_cpu_enable, migt_skip_cpus, migt_cpu_check_rt byte-identical; migt_skip_cpus_rt (gate identical, D3 tail), migt_should_skip_this_cpu_rt and migt_should_skip_migrate (gate identical, D4), migt_choose_exclusive_cpu (gate identical, branch layout + D5). Cross-reference table of every GC symbol (is_doing_gc, gc_booster_enable, gc_thread_name, gc_main_thread_name, game_main_gc_task, gc_booster_reset) per function: identical counts stock vs ours.
   - **xr_set_next_freq: MATCHES** for the GC part: every migt_enable path (glk / flt / limiter) passes `if (is_doing_gc) f = policy->max` right before `*next_freq = (u32)f` (stock 0x97a0); the `!migt_enable && in_perf_mod` path stores without the test (stock `b 0x97b8`), as ours. `policy->max` @0x38 verified by pahole (min 0x34, cur 0x3c, cpu 0x1c). The other 68+ differing instructions are the known G1al codegen.
   - **free_mi_task_struct: MATCHES** (`_raw_write_lock_irqsave` / `_irqrestore`, kmem_cache_free after the unlock; only block layout of the error printk differs).
   - **flt_update_fence_pending / flt_update_gpu: MATCHES** (byte-identical; reloc mapping checked: stock .bss+0xbcb8 = global_frame_info, focused_frame_load / target_runtime1 separate objects).
   - **mi_force_update_freq: MATCHES, offsets VERIFIED** (body byte-identical): +8 = `waltgov_cpu.wg_policy`, +0x30 = `waltgov_cpu.walt_load.ws`, policy +8 = `waltgov_policy.last_ws`. Proof: the stock sched-walt.ko printk "cpu=%d walt_load->ws=%llu and policy->last_ws=%llu" loads exactly `[wgc+0x10]`, `[wgc+0x30]`, `[[wgc+8]+8]`, and the public cpufreq_walt.c/walt.h layout gives the same offsets. Semantics: skip the cluster if `walt_load.ws < wg_policy->last_ws` (signed difference, stale cpu window). Cosmetic: rename flt.c `ts` fields to `walt_load_ws` / `last_ws` and fix the comment "already updated".
4. **Hook ids: MATCHES.** Per-function sequences of register/unregister_plat_func (id, target) are identical stock vs ours in all 10 functions: migt_sched_init 16,22,27,24,25,26,23,29,28,40 (+ rvh try_to_wake_up_success after 16); migt_sched_exit same ids, 40 last; init_module 13,14,15,20,39,30; cleanup_module 30,13,14,15,20,39; mist_frame_load_init/exit 35,36,38,37; game_load_init/exit 17; xr_sched_init/exit 18,21,19. plat_common slots: `plat_update_frame_load` reads table+0x238 (slot 35), flt_enable 0x248 (36), get_wakeup_info 0x258 (37), mi_force_update_freq 0x268 (38), enable_gpsync 0x278 (39), mi_game_schedule 0x288 (40), mi_set_next_freq 0x118 (17): consistent; the kCFI hash each wrapper checks equals our preamble word (0x8dc98cd3, 0x36b1c5a6, 0x1703dde1, 0x4654aab3, 0x7f318e9b, 0x40d4faad, 0x1d710a0e). init_module error paths read branch by branch: wq fail -> qos unwind; proc_mkdir fail -> destroy wq; misc_register / alloc_chrdev_region / cdev_add / class_create / device_create unwinds (incl. the stock quirk "PTR_ERR(NULL)=0 continues init") and the first-stage qos failure -> printk + cpufreq_register_notifier, on error unregister + game_load_exit + migt_sched_exit: same as ours. cleanup_module call sequence identical. migt_sched_init: D2.
5. **Module parameters: MATCHES.** `__param` entries: perm 0x1a4 (0644), level -1, flags 0, ops/arg identical (gc_booster_enable: {set_gc_booster_enable, param_get_int}, &gc_booster_enable; gc_thread_name / gc_main_thread_name: {param_set_task_name, param_get_string}, kparam_string {maxlen 16, the right buffer}). gc_booster_enable / is_doing_gc / names in .bss (zero by default: booster off). set_gc_booster_enable, param_set_task_name, gc_booster_reset byte-identical: sscanf "%d" != 1 -> -EINVAL; param_set_int; value 0 -> reset (enable=0, is_doing_gc=0, both names zeroed); task name: strip one trailing '\n' in place, then param_set_copystring (>15 chars -> -ENOSPC). Readers use fortified strnlen(.,16) with fortify_panic at 16/17 in both.
6. **Signedness / masks / ordering:** is_doing_gc read with ldar (atomic_read under LTO), written with plain str (atomic_set) in both; the test-and-set in android_rvh_try_to_wake_up_success is non-atomic in both (byte-identical). No other divergence found in the G14c-touched code beyond D1..D5.

## Not verified

- Runtime behaviour (no hardware test); whether user space on the global ROM ever writes gc_booster_enable / gc_*thread_name.
- migt_hardwork outside the GC parts and migt_should_skip_migrate's body beyond the gate were only call-multiset / spot checked (old CN-level residuals from G1ak/G1al).
- Whether a future firmware adds a caller of plat_mi_game_schedule (then migt_game_schedule becomes live; its logic matches the stock).
