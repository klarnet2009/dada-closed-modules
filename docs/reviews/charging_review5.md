## 3. Findings (ranked by battery-safety impact)

### HIGH

**QW-1 (HIGH) quick_wireless: `zone_changed` is never set or consumed, so the CC/CV stage is not re-selected after a battery-temperature zone change.**
Stock `mca_wireless_quick_charge_can_tbat_do_charge` +0x288..+0x298 stores `proc_data.zone_changed (+0x398) = 1` whenever it switches to a new temperature zone / volt_para table (symcmp only-stock `S@298 st(strb;a0+920;1)`). Stock `mca_wireless_quick_charge_select_stage` +0x194..+0x1bc: `if (new_stage > cur_stage || zone_changed || fastcharge != ffc_flag) { cur_stage = new_stage; zone_changed = 0; }` (and the same for the parallel stages at +0x4ac/+0x4c0). Ours: `mca_quick_wireless.c:1163` `if (stage > info->proc_data.cur_stage[i] || (ffc_flag != info->proc_data.ffc_flag))` and `can_tbat_do_charge` (1310-1325) never writes zone_changed (the field exists only in the header, `mca_quick_wireless.h:309`).
Failure scenario on dada (DT tables): 20-35 C uses `ffc_volt_para1_3` (5 rows), 15-20 C uses `ffc_volt_para1_2` (4 rows). Battery cools below 20 C late in a quick wireless charge (cur_stage 8, row 4 = 4570 mV): the stock re-selects the stage from the new 4-row table; ours keeps cur_stage 8, so `volt_para[cur_stage / 2]` (select_max_ibat, select_min_vbatt_th, regulation, check_charge_done) reads entry 4 of a 4-entry kcalloc'ed table = heap memory past the end, used as CV voltage threshold / current_max / current_min (wrong CV target and wrong termination). In the other direction a kept higher stage maps to different rows of the new table (thresholds of another zone). Backstops that remain: zone `temp_max_cur`, `max_vbat` (4490) abnormal check, CP/FG hardware OVP. Fix: set zone_changed in can_tbat_do_charge where the stock does and add the `|| zone_changed` / clear in both select_stage tests.

### MEDIUM

**QW-2 (MEDIUM) quick_wireless process_event ignores MCA_EVENT FG_OTA_PROCESS (73).** Stock switch range `event - 2 <= 0x47` (+0x60) and case 73 at +0x400..+0x430: log "fg_ota_process event %d", `mca_vote(chg_disable_voter /*+0x20*/, "fg_ota_process", true, value)`. Ours: range `<= 67` (symcmp `O@64 ... 67`), no case. Scenario: during a gauge firmware/data-flash update the stock blocks CP quick wireless charging; ours keeps regulating on gauge readings that are unavailable or stale during the OTA. (Sender of event 73 not identified in this review; bq27z561 itself only sends event 67 from probe.)

**QW-3 (MEDIUM, safe-side) quick_wireless ignores CP_NEW_MODE (37).** Stock +0x2bc..+0x2d8 / +0x368..+0x378: if `enable_quickchg`: log "new CP mode, stop quick charge", cancel monitor_work, stop_charging (restart in the new mode). basic_wireless `change_cp_mode_workfunc` (UUID 0x0e0e0205 on FUDA1661, 15000 jiffies after the 4:1 start) sends it; ours continues the 4:1 session with the FCC 6000 vote (lower current, not an over-current).

**BQ-1 (MEDIUM) bq27z561: the 19 "family B" accessors use STOCK register indices on the TEMPLATE register table.** Stock `bq27z561_regs` (46 B): `00 06 08 0c 14 0a 0e 1e 16 18 12 10 2a 2c ...`; built (44 B): `00 06 08 0c 14 0a 16 18 12 10 2a 2c ...` (the stock has two more registers at index 6/7). `bq_fg_probe` copies the 44-byte template table into `bq->regs` (`memcpy(bq->regs, bq27z561_regs, NUM_REGS)`), the template accessors use the template enum (consistent, e.g. fg_read_rsoc ldrb +348 vs stock +350), but the G13l accessors hard-code the stock indices `bq->regs[22]..[45]` (`bq27z561.c:551..`, symcmp facts "equal" because the struct offset is equal). Every one reads the register two entries further on (regs[22] 0x7b instead of 0x78, regs[30] 0x87 instead of 0x85, ...), and regs[44]/[45] are 0 (register 0x00 CONTROL instead of 0x97/0x99). Read-only, so no gauge write, but over_peak_flag / current_dev / average_current / learning values exported through sysfs/ops are wrong. Fix: take the stock 46-entry table and enum, or translate the indices.

**BQ-2 (MEDIUM) bq27z561 core readers are still the template** (fg_read_volt / fg_read_current / fg_read_temperature / fg_read_rsoc, fed to every charging strategy): voltage accepted up to 10000 mV (ours `cmp 10001`) where the stock rejects > 5000 mV as "volt out of range" and keeps the last value (stock `cmp 5001` lo); mutex_lock instead of the stock trylock + usleep(40,50) loop with the `ota_updating (+1156)` early exit; fg_read_rsoc does not return the cached RSOC (+460) on an I2C error. A garbage I2C read of 5..10 V is passed to the strategies as vbat (spurious OVP / termination, safe-side but wrong). Temperature range and current range constants equal stock.

**QC-1 (MEDIUM, verdict-level) mca_strategy_quickchg regulation / monitor_work are template.** symcmp: `mca_quick_charge_regulation` 389 vs 111 facts (343 stock-only), `mca_quick_charge_monitor_work` 305 vs 150 (189 stock-only); the restored check_cp_work_mode / cp_check_initial_mode / update_batt_para / parallel_judge_temp / update_jeita_fcc are `__used` and unreachable. The 90 W wired PPS loop (vstep, ibus compensation, buck-parallel, anti-overvoltage, boost hold-off, "prevent ovp: vth - vbat < 20mv") is therefore not the stock's. `mca_qc_quick_charge_regulation` (QC3/QC3.5): facts 85/82, 7 stock-only = the UP/DOWN trend conditions composed differently (14 guard diffs): NOT proven equal.

### LOW

- **QC-2 (LOW, inactive on dada)** `mca_quick_charge_check_chg_done` (`mca_strategy_quickchg.c:1998`) inverts the stock condition: stock +0x3c..+0x40 `cbz w0` -> +0x84 reads the parallel cell voltages when `strategy_class_fg_ops_get_voltage()` SUCCEEDS; ours does it when it FAILS. The "1 word differs" of the STATUS is this branch. Dada: batt_type 0 and hardware_cv 1 (returns before), so no effect.
- **BK-1 (LOW, no-op)** buckchg `process_batt_btb_change` (`mca_strategy_buckchg.c:856`): stock releases the `master_batt_missing` override on input_limit only when value == 0 (+0x70 `b +0xc0` skips it on the battery-missing path); ours always. No OS4 module sets that override (string only in buckchg), so no effect; the STATUS "select vs two votes only" is incomplete.
- **QW-4 (LOW, inactive on dada)** quick_wireless disconnect does not clear `taper_done_no_retry` (stock +0xa8; only set by the hw taper, hardware_cv absent -> 0); startup checks charge_flag after soc / check_condition (stock first) and misses three `change_bridge(0)` calls (platform 5 only).
- **QW-5 (LOW, inactive on dada)** base-flip-only differences: select_max_ibat (set_flip_cur static last_flip_curr_max missing, extra get_parallel_volt_para calls), select_stage parallel stages, parse_batt_info base/flip FFC cc para (all 100 stock-only facts behind `support_base_flip`, +388), get_parallel_volt_para 2/2.
- **BQ-3 (LOW)** built bq27z561 has a `__bug_table` entry at fg_get_device_name+452 that the stock has not (a BUG trap in a gauge accessor: not analysed).
