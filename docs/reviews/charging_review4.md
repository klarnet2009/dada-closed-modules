## 2. Method

1. Reproduction: snapshot sources compiled with the ThinLTO-emulation fast loop (`review7/bin/cl7.sh`, stubs_g13a / stubs_g13b) -> every function byte-identical to the G13e Kleaf `.ko` (`<work-dir>`, copied to `review7/built`), only `init_module` (and smart_charge_probe relocs) differ. ## 3. Findings (ranked by battery-safety impact)

### HIGH

**Q-1 (HIGH) quick_wireless `stop_charging` re-enables the PMIC buck charger directly, bypassing the chg_enable voter.**
`mca_quick_wireless.c:476-482`: `if (wls_plugin && !soc_limit_enable && temp > -10 && (chgr_stat == TERMINATION(5) || chgr_stat == CHARGING_DISABLED(7))) { platform_class_buckchg_ops_set_chg(MAIN, false); platform_class_buckchg_ops_set_chg(MAIN, true); }`.
Stock (`mca_wireless_quick_charge_stop_charging` +0x228..+0x28c): condition `wls_plugin && (chgr_stat & ~2) == 5` (no temp / soc_limit test), action `mca_vote(info->chg_enable_voter /* +0x10, found by mca_find_votable("chg_enable") in probe +0x688 */, "quickchg", true, 0); msleep(200); mca_vote(..., "quickchg", true, 1)`. The stock module does not even import `platform_class_buckchg_ops_set_chg` (compare_ko_v2 imports: built-only); our probe never looks up the "chg_enable" votable (symcmp S@688 only-stock).
Failure scenario: battery hot -> JEITA (or vbat_ovp / batt_miss / soc_limit from another client) votes chg_enable off -> CP quick charge stops -> `chgr_stat == CHARGING_DISABLED` -> ours writes "charger enable" straight to the PMIC; the chg_enable voter's effective result did not change, so nobody re-disables the charger until some later vote change. Buck charging continues against an active over-temperature / over-voltage stop. Also reached from the extra template stop in `select_max_ibat` ("fcc less than 2.2A", Q-6).

**B-1 (HIGH on dada, snapshot only; G13f is fixing it) buckchg monitor: stock CP-absent reaction missing.**
Stock `strategy_buckchg_monitor_workfunc` +0x578..+0x658 (inlined `strategy_buckchg_check_cp_i2c_err`): when not quick-charging and `vusb_ovp_location != 0`: `platform_class_cp_get_present(0,&p)`; absent or I2C error -> counter (dev+200) up to 6 ("CP not present, retrying"), then if `vusb_ovp_location == 1` (BEFORE_CP): `mca_vote(input_voltage_voter /*dev+232*/, "cp_i2c_error", true, 0)` = force 5 V, log "vusb_ovp_location is BEFORE_CP, forcing 5V, reporting error". Snapshot: absent (the 3 strings and the import `platform_class_cp_get_present` are stock-only). dada has `vusb_ovp_location = 1`, so this path is live: with a dead/absent CP the snapshot keeps negotiating 9 V+ in front of an OVP that sits before the CP. The G13f source of 22:12 adds `strategy_buckchg_check_cp_i2c_err` (lines 1626-1653): its logic matches my decode of the stock block; re-verify the call site (stock calls it only when `mca_strategy_func_get_status(QUICK_CHARGE, CHARGING) != 1`, +0x540..+0x554) after G13f's build.

### MEDIUM

**Q-2 (MEDIUM, functional, live on dada) quick_wireless probe never parses `max_rx_vout_request` -> `vout_set_max = 0`.** Stock probe +0x1ec `mca_parse_dts_u32(node, "max_rx_vout_request", &info->vout_set_max /*+380*/, 19500)` (dada DT: 19500). Ours: no parse (`grep vout_set_max` = only the clamp at `mca_quick_wireless.c:1577`), the struct is kzalloc'ed. `req_adp_volt` (stock-identical clamp) therefore requests RX vout **0 mV** on every regulation step of monitor_work -> CP input collapses / quick wireless charging aborts. Not an over-voltage, but quick wireless charging cannot work. Also not parsed: `support-cp-num-switch`, `try-single-cp-fcc` (6000), `sw_cv_taper_reduce_cv`, `pps_high_taper_fcc_thr`, `hardware_cv` (stock +0x15c..+0x234).

**Q-3 (MEDIUM, over-current at CP start) start ICL 700 mA instead of 500 mA for ibat_max < 7000.** `mca_quick_wireless.h:108` `MCA_WLS_QUICK_CHG_STARTUP_SMALL_ICL_MA 700`; stock start_charging +0x268..+0x2a8: `ibat>=8000: icl 800, up 500; ibat>=7000: 700/400; else icl 500, up = ibat>=5000 ? 400 : 200` (`mov w9,#0x1f4; str [x19,#0x378]`). Ours (`mca_quick_wireless.c:841-850`): `<7000 -> 700 / 200`. The "wireless_qc" ICL vote at the CP start (+0x3f4) is 200 mA (40 %) higher than stock for every lower-power TX / thermally limited start.

**Q-4 (MEDIUM, missing protection default) quick_wireless probe does not cast the initial `batt_miss` vote.** Stock probe +0x79c..+0x7b0 `mca_vote(chg_disable_voter /*+32*/, "batt_miss", true, 1)` right after the voters are created (quick charge disabled until the battery BTB/auth event clears it). Ours: no vote -> CP quick wireless charging is allowed before battery presence is confirmed. Also missing: the "cp is not ready, wait for it" deferral (`platform_class_cp_get_probe_ok(0/1)`, +0x894/+0x8a0).

**W-1 (MEDIUM, thermal limit lost in a corner case) basic_wireless `set_auth_30w_ichg` uses if/else-if where the stock ORs.** `mca_basic_wireless.c:781-787`. Stock (+0x14..+0x80): `auth30 = (adapter_type == 12 /*PD_40W*/ && !magnet_tx_flag) || (uuid_value == 0x0e0e0205 && project_vendor == 3 && !is_4_1_mode)`. Ours evaluates the UUID clause only when `adapter_type != 12`. Case `adapter_type == 40W && magnet_tx_flag && uuid 0x0e0e0205 && FUDA1661 && 2:1`: stock votes `charge_limit_voter "wireless_thermal_30w"` + `sw_thermal_ichg "wireless_thermal"`, ours releases "wireless_thermal_30w" -> the 30 W thermal FCC limit is not applied (symcmp: 3 stock-only conds, guard diff on the mca_vote).

**W-2 (MEDIUM, template chg_handler inside process_irq) safety-relevant stock reactions missing in `strategy_wireless_process_irq`:**
- weak EPP 15 W TX: stock +0xd74..+0xdcc `if (uuid_value == 0x09010903 && tx_max_power == 15) { strategy_wireless_stepper_pmic_icl(info, 1300, 850, 500); mca_vote(input_limit_voter, "weak_epp15w_tx", true, 850); }` (and releases on !online +0xdd0..+0xe24).
