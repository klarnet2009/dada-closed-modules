Reference: `<work-dir>` (copied to `<work-dir>`). None of the three modules binds on dada (global DTB: only cirrus,cs35l43 + qcom wsa883x/wsa884x/wcd939x): the goal is complete sources. ## 1. Method (what was new compared to G40g)
Lessons of G40g: the earlier verdicts "no behaviour difference" were wrong twice, and `strdiff2.sh` normalised our `"%s(): %s(): "` to `"%s(): "`, which HID a real log difference (our messages printed the function name twice, 13 sites). New tools (work/re/src/g41a_tools):
- `pdiff.py`: per-function normalised listing diff of raw `llvm-objdump -dr`: registers masked, branch targets masked, relocation targets RESOLVED (string text, data symbol, `.text+off` -> function name; stock `.rodata+off` and our `.rodata.str1.1+off` become the same `S"text"`), kCFI/pac/bti dropped, difflib hunks with context (`CTX`), filter (`FILT`), `RES=1` = residual multiset after cancelling moved lines (condition polarity ignored in the multiset, so spots were then read by path), `DROP` noise filter.
- `seq.py`: sequence of calls with the immediate arguments known at the call (register writes `tfa_reg_write(reg,val)`), difflib.
- `tgt.py`: for a message string, the block start and which branch (after which call) leads into it: proves which condition prints which message when block order differs.
- `fixpf.py`, `ed_*.py`: the source edits (CRLF/LF preserved).
Builds: real Kleaf (kb.sh, `--lto=none --config=stamp`), compare_ko_v2 + preamble_cmp, tbl_audit3.py (g33a) on the final builds.

## 3. BEHAVIOUR differences found in G41a and fixed (all proven from the raw stock disassembly)
**tfa98xx**
1. `tfa9894_specific` rev 0x2a94/0x3a94 (stock: `(rev-0xa94) ror 12` in {2,3}): stock writes 01=15da, 02=51e8, **04=0200**, 52, 53, 57, **61=0032**, 71=6ecf, **72=b4a9**, 73=38c8, 76, 80, 81=5799, 82; NO reg 0. Ours wrote reg 0 (a245), no reg 4, 61=0033, 72=34a9. Fixed; `seq.py`: call sequence IDENTICAL (28 calls). Also removed the extra `if (tfa->verbose) if (N2) pr_debug("check_correct")`.
2. `tfa9873_specific`, `tfa9874_specific`, `tfa9878_specific`: stock sets `tfa->interrupt_enable[0] = 0x11e` and calls `tfa_irq_init` in the common tail after the switch (also after the default message); ours missed it for 9873/9874 and had no `interrupt_enable` store for 9878. `tfa9878_specific` case 0x0a78: stock has NO `0x83 = 0x9a` write, ours had it. Fixed.
3. `tfa9865_specific` case 0x0a65/0x2a65: stock writes `0xd2 = 0` before `0xda = 2`; ours lacked the 0xd2 write. Fixed.
4. `tfa9888_specific`, `tfa9912_specific`: stock prints `"Warning: Optimal settings not found for device with revid = 0x%x \n"` in the unknown-rev case; ours silent. Fixed.
5. `tfa_status`: stock prints an empty info line and calls `tfa->dev_ops.tfa_status` when set (tfa9875 sets it) and returns its result; ours ignored the hook. Fixed.
6. `tfa_dev_set_state` (the "returns 7" item): in the TFA_STATE_INIT_CF wait loop stock returns 7 (`tfa_error_max`) when `tfa98xx_dsp_system_stable` reports a non-zero error; ours returned the error code itself. Fixed. (per-iteration print `"%s error=%d  ready=%d\n"` was already in the wrapper.)
7. debugfs: `pga_gain_get`: stock takes no lock, no error check, `*val = (u32)tfa_get_pga_gain()`; `pga_gain_set`: `val > 7` -> -EINVAL, failing set -> -EINVAL, no lock; `temp_get`: sign-extends the s16, never fails. `rpc_read` / `rpc_send`: stock has NO probus (`send_tfa_cal_apr`) branch (ours returned -EOPNOTSUPP-like errors via the stub). Fixed to the stock behaviour.
8. ALSA: `tfa98xx_get_miid`, `get_pcm_id`, `spksw_gpio_get`: stock writes `ucontrol->value.enumerated.item[0]` (32-bit store), ours wrote the 64-bit `integer.value[0]`. Fixed.
9. Driver version string: stock `v6.13._xiaomi` (module init banner, `tfa98xx_rev`, debugfs `version`), ours `v6.5.3`. Fixed (`TFA98XX_API_REV_STR`); the `sscanf("v%d.%d.%d")` returns 2 in stock too, so the "invalid version string." message (not in stock) was removed.
10. NULL ops guards: stock `tfa_dev_get_mtpb/get_swvstep/set_swvstep/set_swprof` return 0, `tfa_dev_get_swprof` returns -1, `tfa_mem_read/write` return 0 when the op pointer is NULL (the 986x ops leave get_mtpb NULL); ours called through NULL. Fixed for these 7.
11. Log text (messages): 13 messages printed `"%s(): %s(): ..."` (double function name: explicit `%s():` on top of `pr_fmt`): fixed in 13 sites (`tfa98xx_tfa_start`, `dsp_init` goodix, `get/set/info_vstep`, `append_i2c_address` x3, `No device available`...). `Calibration failed! \n`, `Writing cmd=... \n` (trailing space), `\nWarning: Optimal settings ...` (leading newline for 9872/9874), `Error: Current device has no secondary Re25 channel \n` (info level, trailing space), `\nError: Unable to read revid ...` (no level: `printk`), `other smartpa type already set, no need to probe` (no newline), `pr_info("\n")` (info, was debug) in tfa_dsp_msg / msg_read.
