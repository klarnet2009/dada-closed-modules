## 2. Method

1. Snapshot of the six source dirs at 04:31 (md5: `work/a17/review/charging_review2_snapshot_md5.txt`; unchanged at 05:00). Recompiled with the ThinLTO fast loop in `<work-dir>` (copy of the review `cl.sh`): every function of all six modules is identical (bytes + resolved relocations) to the agents' newest Kleaf `.ko` (g2l: fg_comp, antiburn; g2k: revchg, business, pwm_fan; g2j: jeita) except `init_module` (`__this_module` ext vs obj, link artefact). So the reviewed binaries are exactly what the current sources produce.
2. `compare_ko_v2.py -v` (stock vs Kleaf `.ko`) for all six (`<work-dir>`).
3. `semfp.py -g` (call multiset + arguments) on every differing function.
4. New: `work/a17/review/tools2/lst3.py` (listing with every relocation resolved by `compare_ko_v2.Elf`, statics by name), `ldiff2.py` (aligned diff + **control-flow check**: every branch in the aligned part must hit the mapped target; `-R` masks register numbers), `ldiff3.py` (adds moved-block pairing so block placement differences do not hide branch-target changes). All 42 differing functions were run through these; every remaining hunk and every branch mismatch was read by hand against the stock listing and the C source. `tools2/jtpart.py` compares jump-table case partitions, `tools2/odump.py` dumps objects with relocations, `tools2/fdtgrep.py` parses the OS4 `dtbo.img` (stdlib FDT parser) for the DT facts used below.
5. For mca_buckchg_jeita `monitor_work` (JEITA = temperature-dependent current/voltage, never reviewed before) the full stock listing (1218 insns) was read line by line against the C source.

Why the earlier tools missed things: semfp compares multisets of calls/arguments/immediates; a changed branch target (same instructions, different successor) is invisible to it. Five of the findings below (FG-1, FG-4, J-2, R-1, R-2) are exactly that: identical instruction text, one different branch target. The STATUS "1 word / layout" notes for set_charging_done, process_event and enable_reverse_charge are these real differences.

## 4. Findings per module (most severe first)

### 4.1 mca_buckchg_jeita - REAL DIFFERENCES
**J-1 (HIGH, active on dada) smart-charge interface registered with the wrong type.** compare_ko_v2 `objects` FAIL: `g_jeita_smartchg_if_ops` first word = 4 in the stock (`.data+0xf8`: `04000000...`, relocs +0x10 delta_fv_callback, +0x48 update_baa_para), 3 in ours. Stock types of all registrants (from the stock `.data`): mca_strategy_buckchg 0, mca_basic_wireless 1, mca_strategy_quickchg 2, mca_quick_wireless 3, mca_buckchg_jeita 4, mca_charger_thermal 5. Stock `mca_smartchg_if_ops_register`: `ldr w3,[x0]; cmp w3,#6; b.lo; str x8,[x9,x3,lsl#3]` (g_ops[type] = ops). Ours therefore overwrites (or is overwritten by) the quick-wireless slot; slot 4 stays NULL, so smart-charge `delta_fv` (float-voltage reduction for battery aging / protection) and the BAA JEITA-table update never reach JEITA, and quick-wireless may lose its callbacks. Root cause: `smart_chg_class.h` in every stubs tree (`stubs_a17A/B, g2h..g2k, g5`) has `BUCK 0, QC 1, WL_QC 2, JEITA 3, WL_BASIC 4 (guess), THERMAL 5`; the stock order is `BUCK 0, WL_BUCK/BASIC 1, QC 2, WL_QC 3, JEITA 4, THERMAL 5`. Fix the enum. Cross-module: the same header is used by the rebuilt mca_quick_wireless, mca_strategy_quickchg, mca_basic_wireless (uses an undefined `..._WL_BUCK`) and mca_smart_charge (`get_ops(JEITA/QC/WL_QC)`): not in my scope, must be re-checked (charger_thermal 5 and strategy_buckchg 0 happen to be right).
**J-2 (MEDIUM; HIGH where `support-base-flip` is set; inactive on dada) flip-battery current vote skipped during temperature hysteresis.** Stock `mca_buckchg_flip_jeita_update` (inlined, +0x1170..+0x118c): `tbnz w22,#0,@1178 (hys_affect: skip only the index store); str w21,[x19,#0xc8]; ldr x0,[x19,#0x88] (flip_fcc_voter); mov w3,w23; bl mca_vote(..,"jeita",1,chg_curr)` on every data_change. Ours (+0x1190 `cbz w26,@824`, `mca_buckchg_jeita.c:577-580` `if (!hys_affect && data_change) {index; vote}`) does not vote when hys_affect=1, so a vbat-threshold change inside the temperature hysteresis (including the "s->l" current reduction at high vbat) is not applied to the flip cell. Fix: `if (data_change) { if (!hys_affect) idx = i; mca_vote(...); }`. (Main and base updates match the stock.)
**J-3 (LOW, log only; inactive on dada) `mca_buckchg_jeita_parse_para`** returns 0 when `<name>_ffc` is missing (`mca_buckchg_jeita.c:796`); stock +0x468 `b @184` -> log 904 + `mov w0,#-1`. Probe tolerates -1, so only the "parse dts failed, ret: -1" / "overridden jeita_para" logs differ.
Verified equal (line-by-line read of the stock `monitor_work`): voter_ok/online gating and 1000/3000 ms rescheduling, temperature search loops (`temp < temp_high && temp >= temp_low`, ffc vs normal table), hysteresis selection incl. extreme-cold, vbat_index/min-current helper, `vbat_low_cold_hyst` for `(unsigned)(i-1) < 3`, weak-charger (`adapter_type-1 <= 3` unsigned, `iterm > weak_iterm`), vfloat > 4150 (`cmp #0x1037; b.lt`) -> `jeita-hot` + vterm vote minus delta_fv, else `vbat >= vterm-hyst` -> disable / `< vterm-150` -> enable, dtpt 8/10, en/fcc/vterm/iterm votes and their order, rerun_election, cold_zone, base swocp (count >= 4 && eff != 0 -> fcc eff-100, release when now/1000 > 500-chg; equivalent `ccmp/csinc` vs branches). Guessed items: the temperature conversion `temp<0 ? temp/10-1 : temp/10` equals the stock `~((-t)/10)` for every int (incl. INT_MIN); `delta_fv_callback` (platform_version==3 && country_version==1 -> min 20) is byte-identical to the stock (only the names are guesses). `get_status`: reloads `cur_jeita_index` after a log call (stock keeps it in w21): race-only. probe / parse_dynamic_iterm_by_name: stack-slot / register differences only.
