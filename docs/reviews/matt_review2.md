## 0. Method
- Sources: `work/re/src/matt` (md5 of every .c/.h identical to the server copy `<work-dir>` that G1ag built).
- Stock: OS4 `matt.ko` (`<work-dir>`, copied to `<work-dir>`).
- Ours, rebuilt by me in `<work-dir>`: (a) ThinLTO emulation `o/matt.lto.o` (G1ag's pb_ccl.sh, paths moved to review4); (b) every TU without LTO (`onl/*.o`) = the code shape of the real Kleaf lto=none build, used for the trap check. Base BTF: the existing dump `<work-dir>` (made from the same `kernel.img` + stock matt.ko); field offsets below are from it.
- Tools (mine, scratch `<work-dir>`): `memoff.py` = per function, register-agnostic MULTISET of (load/store opcode, width, immediate offset) for every non-stack memory access, stock vs ours, all 261 functions; `callcnt.py` = per function counts of calls to refcount/lock/free/timer/RCU functions and of all atomics; a brk-count script (stock vs LTO emulation vs non-LTO objects). Plus the existing `sym.py` / `dd.py` (G1ag tools2) for side-by-side reading. All claims below were checked in the disassembly, not taken from STATUS.md.

## 4. Locks
- lock_sock_fast: only in matt_get_info, called only from matt_getsockopt (always_inline, one lock) which runs without the socket lock - no self-deadlock. All lock_sock users (bind, connect, accept, accept_sock_init(newsk), inet_listen/shutdown/connect/accept(sk2), sendmsg, recvmsg, get_sk_addr x2) take it once; nested ones are on a different socket (listener -> newsk) in process context. The G1ad getsockopt double lock is gone.
- spin/bh: matt_hash/unhash `spin_lock_bh`/`spin_unlock_bh` on every exit (incl. the `goto out` paths); matt_rcv bh_lock_sock released on both exits; matt_release_sock unlock_bh/lock_bh pairs = __release_sock; timer wrappers/tasklet balanced; udp hash = mutex, process context only. Same call multisets as stock.
- RCU: matt_sock_lookup returns sk without a reference after rcu_read_unlock - safe only because the caller (UDP encap_rcv) runs inside the IP receive rcu_read_lock and SOCK_RCU_FREE is set at hash time; stock identical.

## 5. STOCK bugs (identical in ours, kept on purpose, not fixed)
- S1 (=I1) matt_sacktag_write_queue reads up to 128 SACK blocks (1 KB) from the packet without checking skb->len: remote out-of-bounds read.
- S2 NEW: matt_rcv_data, out-of-order skb overlapping a queued one: matt_data_queue_ofo frees it (stock 0xb50 `bl kfree_skb_reason`, ours 0xb34), then jumps to the ack part (stock `b @0x5f8`) which reads `mh->flags` from the freed skb data (stock 0x61c `ldrb w24,[x25,#0xc]`, x25 = skb->data loaded at entry; ours 0x7e4; source matt_rcvd.c:403-404 -> :412 -> :135). Remote-triggerable 1-byte use-after-free READ (KASAN report, otherwise a wrong pack/no-pack decision); no write.
- S3 (=I2) SYM_INET_UNREGISTER_PROTOSW resolves inet6_unregister_protosw: on unload the IPv4 protosw is unlinked under inetsw6_lock (list_del_rcu itself is correct).
- S4 init_module: create_workqueue failure -> matt_hash_tables_destroy and `return 0` (matt_init.h:348-350): module stays loaded without protosw/offload/sysctl, rmmod then unregisters never-registered objects. OOM at load only.
- S5 (=I5, extended) matt_init_sock fails with enable=0 -> sk_common_release -> matt_destroy_sock on a socket whose timers/queues/udp_sk/ulp_ops were never initialised. Safe only because sk_prot_alloc zeroes the sock: our kernel has CONFIG_INIT_ON_ALLOC_DEFAULT_ON=y (g7 ikconfig line 7249); with `init_on_alloc=0` on the command line this would del_timer/refcount garbage. Counters are decremented that were never incremented (statistics).
- S6 matt_transmit_skb stores MATT_SKB_CB(oskb)->tx.last_tx_mstamp before the `!oskb` test (stock 0x244 `str w8,[x20,#0x38]`, x20 = 0 when clone_it = 0): unreachable, both callers pass 1.
- I3 (sendmsg returns 0 on errors), I4 (6.6.57 GRO/GSO/defer-free copies), I6 (debug 0x1e prints level 1-4 traces) as in review 1.

## 6. Verdict
No new reconstruction bug found; all G1ag edits are correct and equal to stock; refcounts, locks and field offsets match the stock module-wide. matt MAY be loaded for the first test with net.matt.enable=0 on a TEST phone (not the daily one): what runs then (init_module, cleanup_module, the failing socket-creation path) is stock-equal; check /proc/cmdline has no `init_on_alloc=0` (S5) and expect S3 on rmmod. Before enable=1: mibbr_main middle + matt_raw_skb_dump stay unproven, and S1/S2 are remote-triggerable stock bugs (OOB/UAF reads) - use a throw-away setup, KASAN if possible.
