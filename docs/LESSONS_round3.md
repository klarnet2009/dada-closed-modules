# Lessons from rounds 5 to 7 (strict checks, reviews, charging, Wi-Fi, TEE)

Continuation of `docs/LESSONS_round2.md`. State of 18.10.2026 (evening). Nothing was run on a device.

- **From a kCFI hash to a prototype, with Itanium substitutions.** The type id in front of a function is the low 32 bits of xxHash64 of `_ZTS` plus the Itanium mangling of the function type. A repeated type is written `S_`, `S0_`, ... in the mangling. The first search script (`tools/kcfi/kcq.py`) did not know this, so every prototype with a repeated type was "not found" and some modules carried an invented "unnamed vendor type". `tools/kcfi/kcs.c` applies substitutions, finds up to four arguments in seconds, and closed prototypes that had stayed open for rounds (the `mi_low_lat_mem` probe type and `xr_qi` `do_qos_inherit` first, later `mi_game` `clear_vip_task_type` and `mitee_dlkm` `get_vm_state`). Struct *names* change the hash (`struct waltgov_callback` versus `struct update_util_data`), struct bodies and typedef names do not. So the hash fixes a wrong prototype but cannot remove a forged export CRC that comes from a struct body.
- **"Not found" is a property of the script.** Before declaring that a prototype is unknown, check what the search could not express.
- **A comparison tool that says "relocation layout" can hide content.** The strict tool had filed 21 Wi-Fi objects as layout differences for several rounds; an independent reviewer dumped them word by word and 14 differed in content (a netfilter hook at the wrong point, five policy tables, a default value, an interface combination). Dump what the tool waves through. A scan of relocated string text found a log message that differed while every function byte was equal.
- **Independent review finds what the author's checks cannot.** The reviews found an extra `sock_put` on every `close()` of `matt` (a use-after-free), a wrong hook point, a timer read in the wrong unit (an immediate in jiffies read as milliseconds), enumerator names taken from the wrong enum, and showed that an earlier review and its fixes had themselves contained mistakes. A fix is not reviewed until someone else reads the diff against the stock.
- **A rewrite "by meaning" is not a copy.** Fields read from the shadow copy (`shinfo->gso_segs` where the stock reads the control block), swapped arguments, signed instead of unsigned `% 10`, a missing zeroing, `EXPORT_SYMBOL` instead of `EXPORT_SYMBOL_GPL`, a loop that the stock bounds to three attempts: all invisible to a function-set comparison, all found by a masked-register multiset diff or by reading the stock.
- **Take layouts and enums from the module BTF.** With the module-local start id (141904 for the `mca_*` modules) the BTF gave complete structs and named enums for the three charging modules that were "BLOCKED" for lack of headers; the headers were rewritten from BTF with `_Static_assert` on every offset. Names invented earlier were right in value but wrong in name in two modules.
- **The reference kernel differs from the build kernel.** Stock 6.6.57 versus build 6.6.144: inlined `readl`, `netif_tx_stop_queue`, `poll_wait`, `task_struct` offsets, header line numbers. Look for this first when a function differs by one or two instructions or a line number. A force-included emulation header can equalise it; it is not restored vendor code.
- **A template from another product revision is not the stock.** The XRING `mca_strategy_*` and `mitee` templates compile, but they are an older or newer revision and still carry code that the stock does not have (and lack code that it has); for the TEE transport no template existed at all and the wire format had to be inferred from machine code.
- **Tool artefacts.** The multiset tool counts local calls of the stock as noise and named calls of ours as extra: `+N CALL name` is almost always an artefact. A fast compile loop silently returns the old object after a compile error: always read the compile output. A copied helper script may still point to the scratch directory of a finished round.
- **Do not write the cause before the proof.** Several earlier notes claimed a cause (a flag read by a function, a "set differs" conclusion) that the next round disproved. The STATUS files keep the corrections.
- **Honest labels.** After all these rounds no charging module is strict-equivalent, nothing is tested on hardware, and the Wi-Fi drivers are PARTIAL. "Out of functional differences at the level of binary checking" is the strongest statement the methods allow.
