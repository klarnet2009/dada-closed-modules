# Kernel package: what a full module set looks like, in numbers

State of 18.10.2026. The package itself is **not** published (it consists mostly of stock binaries and a kernel image); this page records what it contains and how it was verified. `docs/kernel_package/manifest.csv` lists every file: module, partition, source, status, verification, hacks, and sha256 of ours and of the stock module. **Nothing in the package was flashed or run on a device.**

## Goal

A kernel image (GKI 6.6.144, CFI on, `MODULE_SIG` on but not forced, `MODULE_SIG_PROTECT` on) plus a set of 640 modules in the HyperOS 4.0 layout (`vendor_ramdisk`, `vendor_dlkm`, `system_dlkm`), in which every module that we have a verified source for is built from that source, and every other module is the unchanged stock binary.

## Composition (640 unique module names, 931 files)

| source | modules | files | meaning |
|---|---|---|---|
| ours | 52 | 69 | built from `reconstructed/` or `ported/`, rebuilt with the real Kleaf build, EQUIVALENT against the OS4 stock **and** strict-clean |
| public-built | 18 | 31 | built from public kernel-tree source, EQUIVALENT against the OS4 stock |
| kernel-build | 96 | 98 | the kernel build's own `system_dlkm` GKI modules (signed with the kernel's key; see below) |
| stock | 474 | 733 | unchanged stock binaries: the charging and gauge family, every PARTIAL / COMPILES-only / BLOCKED module, and every public-source module that was not built or not equivalent |

So 474 of 640 modules are plain stock bytes. This is "our sources for the modules that have them, on top of the stock set", not a complete rebuild from source. The 18 public-built modules are the successful part of a sample of 25 (72%) of the easy kind (one `.c` file, no stub providers); the other 481 name-matched public modules were not tried, and the rate must not be extrapolated. For 7 of the 25 the stock and our tree differ in headers (the stock calls the out-of-line `log_read_mmio` in `readl()`, our 6.6.144 headers inline it), in a newer upstream function, or in private headers.

## Verification of the package (`tools/verify_pkg.py`, result PASS)

- CRC of every import against the kernel's `Module.symvers` or another package module: 0 mismatches, 0 unresolved imports.
- vermagic: with `MODVERSIONS`, only the flags tail (`SMP preempt mod_unload modversions aarch64`) is compared: 640 of 640 equal.
- `depends=`: 0 names missing, 0 differences from the stock (modules that were built against stub providers have their `depends=` set back to the stock value with `tools/modinfo_fix.py`, which touches only `.modinfo`).
- Exports: no collisions, no unsigned module exporting a protected symbol (those would be refused with -EACCES).
- kCFI: 70 modules differ from the stock; 0 kCFI preamble mismatches against the stock for them; 208 vendor-hook probe registrations of the whole stock set were checked against the hash the kernel expects, 0 drifts.
- Strict check (`compare_ko_v2.py`) of all 100 non-stock files: 6 strict-equivalent, 86 differ in metadata only, 8 differ in bug-table line numbers only, 0 REAL differences. Two modules (`minidump`, `tas25xx_dlkm`) are EQUIVALENT only after `tools/crc_patch2.py` sets 1 import CRC and 2 export CRCs to the stock values.
- Load simulation of the three load lists (149 + 561 + 80 entries): no dependency cycle, no dependency unavailable at its stage.
- Rebuild check: all 52 + 18 modules were rebuilt from the sources and every `.ko` is byte-identical to the build recorded in the package (69 of 69).

## Module signatures

The kernel has `CONFIG_MODULE_SIG=y` without `MODULE_SIG_FORCE`, `MODULE_SIG_PROTECT=y` and `CONFIG_APEX_RELAX_GKI_MODULE_KMI=y` (an own patch: unsigned modules may import symbols outside the KMI list; the export-side protection is untouched). The stock vendor modules are unsigned (544 of 638), so are ours, and they load the same way. The 96 stock `system_dlkm` GKI modules are signed with a different autogenerated key than the one of this kernel build; on this kernel they count as unsigned and 30 of them export protected symbols, so they would be refused. That is why `system_dlkm` in the package is the kernel build's own output.

## Choices that follow from the verification

- `binder_gki` is stock: our build is PARTIAL (9 of 10 functions) and an earlier build had a wrong kCFI hash in its probe (`docs/VERIFICATION_METHODS.md`).
- `minet` is stock (two promoted functions carry an extra kCFI word that the stock does not have).
- `dcvs_main` is stock (PARTIAL, 15 of 18 functions).
- `mii` is the kernel's own signed build, not ours (ours is correct but unsigned and exports protected symbols).
- `synaptics_tcm2` moved from stock to ours after a clean strict comparison (240 functions, 12066 relocations, 167 kCFI words).
- The charging and gauge family and every module listed as "do not load" in `docs/STATUS_AND_LIMITS.md` are stock in the package.

## Not done on purpose, not checked

- No kernel config change, no repacking of `vendor_boot`/`vendor_dlkm`/`system_dlkm` images, no `boot.img`.
- Behaviour on hardware: not one module was run.
- Third-party firmware inside stock modules (`ufs_ffu`: UFS firmware images; `nuvolta_1652`: wireless charger firmware arrays) stays in the local package only; it is never published.
